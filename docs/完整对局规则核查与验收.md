# 完整对局规则核查与验收

依据：用户提供的 v11.5 PDF 文字提取，核心规则第 8–11、20–22 页，认证行动 2025 第 105–107 页。

## 本轮发现并修复

- **主要行动计分错误**：原实现重复加全部 VP；第 107 页要求奖励该项 VP 的一半，向上取整。已修正模型、界面、测试和说明，满分 21VP。
- 战前先手权和第一转折点先手权分开记录，战前非先手方获得重投卡。
- 装备部署确认后，双方按三组轮流部署。10 人为 4/3/3，7 人为 3/2/2，默认隐匿。
- 保留上个转折点先手权直到下一次决定；记录拼骰胜方及其选择的先手方。第一至第三转折点的卡发给拼骰败者，不是自动发给非先手方。
- 先手权卡可查看、消耗并记录修正或重投结果。实体拼骰、交替用卡及连续让过由双方完成后确认。
- 战略计划交替使用，记录名称和 CP 费用，同名计划每轮一次，连续让过结束；第一轮秘密选择主要行动也是一次战略计划。
- 交战阶段记录当前玩家、激活特工、命令、AP、行动、待机与反应。基本行动重复、移动冲突、隐匿限制有提示；特殊规则需填写依据。反应为一个有效费用 1AP 的非戒备行动，且每名特工每轮一次。
- 记录目标控制、携带标识、装备使用次数及其他任务状态；计谋 CP 和 VP/耐伤变更写入日志。
- 射击选择目标并预填豁免，攻防骰及重投序列关联到本场对局。近战不使用射击抵挡模型：双方按实体攻击骰交替出击/格挡后，记录武器、过程及双方剩余耐伤。
- 终局核对双方击杀等级，较高方奖励 1VP；主要行动保密至终局。结束后的对局不能继续修改状态，可撤销终局恢复。
- 保存最近 30 个可撤销状态；完整时间线可查看和导出。原存档解析失败时保留原数据并报错，避免默默清空。
- 战前向导在系统回收活动后恢复填写内容。

## 自动化边界

这是对局记录与流程引导工具。模型位置、视线、距离、控制范围、目标合法性及阵营特殊规则由玩家判断；任务达成和 VP 由玩家确认。装备、战术行动与目标状态仍可用文字记录。阵营特例（不计入击杀、复活等）可手动校正。

已有的骰子解析和射击结算算法未扩展。没有加入三维战场裁判或全阵营规则引擎。

## 验证方式

- 使用项目自带 JDK 17 和 Android SDK。
- 单元测试覆盖主要行动奖励、CP、击杀表、先手权卡归属、部署分组、交替计划、AP 和每轮反应限制。
- Android Lint 和 Debug APK 构建。
- 手机模拟器：wh40k_test；平板模拟器：whkt_tablet。通过 ADB 安装后检查实际界面、向导和状态恢复。
- tools/emulator_ui.rb 提供基于可见文字的模拟器操作，tools/seed_emulator_rosters.rb 仅向无既有名单的模拟器写入演示编成。
