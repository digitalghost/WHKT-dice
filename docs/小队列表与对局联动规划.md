# 小队列表、规则详情与骰盘联动规划

更新：2026-09-23

## 目标

把当前单一的“小队编成”页面扩展成完整流程：

```text
我的小队列表
  → 选择当前对局小队
  → 查看成员
  → 选择该成员的一件武器
  → 带着武器档案进入攻防骰盘
```

应用仍不自动判断编成、武器搭配或复杂规则是否合法；这些由玩家协商。应用负责保存、查阅规则和把明确的武器数值带入骰盘。

## 页面结构

### 1. 我的小队列表

- 列出设备上保存的全部小队，不再限制为“每种卡库只有一份”。
- 每张列表卡显示：小队名称、所属卡库、成员数、更新时间。
- 提供新建、编辑、复制、删除。
- 只能有一个“当前对局小队”；切换时立即保存其 ID。
- 从骰盘进入小队功能时，首先打开此列表，而不是直接进入编辑器。

### 2. 小队编成

- 继续使用现有候选成员与当前名单布局。
- 编辑器接收 `rosterId`，只修改指定名单。
- 新建时先选择卡库，再进入空名单。

### 3. 当前对局小队

- 以紧凑成员卡列出当前小队。
- 展示每名成员已选武器及能力。
- 点击武器主体：选择该武器并进入骰盘。
- 点击武器关键字：只打开该关键字说明，不触发投骰。
- 点击能力名称：打开该能力完整说明。

## 规则信息模型

现有 `WeaponOption.profile` 是用于显示的整段文字，不适合稳定联动。应逐步拆成结构化字段：

```text
WeaponProfile
  id, name, kind
  attacks, hit, normalDamage, criticalDamage
  keywords: List<RuleRef>

RuleDefinition
  id, name, parameter, description

AbilityDefinition
  id, name, apCost, description

OperativeTemplate
  weapons: List<WeaponProfile>
  abilities: List<AbilityDefinition>
```

- `RuleDefinition` 作为唯一规则词典，骰盘速查和小队页面共用，避免两份文字不一致。
- 带数值的规则拆成“规则 ID + 参数”，例如 `穿刺 + 1`、`致命 + 5+`。
- 队伍专属规则和成员能力放入 `AbilityDefinition`，不混进通用武器关键字。
- 未收录说明的条目仍显示名称，并明确标记“说明待补充”，不能悄悄隐藏。

## 规则详情交互

参考 KTDash 的信息层级，但沿用本应用的视觉语言：

- 武器档案保持紧凑的一行或两行。
- 关键字显示为可点击的小标签，紧跟武器数值。
- 能力以名称列表显示，点击名称弹出半透明详情浮层。
- 浮层只展示当前规则或能力，包含名称、参数、正文和关闭按钮。
- 点击武器行的空白区域才进入骰盘，点击标签不会误触发跳转。

## 骰盘联动

选择武器后，通过明确的 `SelectedWeaponPayload` 传给骰盘：

```text
rosterId, memberId, weaponId
weaponName, attacks, hit
normalDamage, criticalDamage
keywords
```

骰盘自动填入攻击骰数量、命中值、普通伤害和暴击伤害，并显示武器名称与关键字。现阶段只保留已有的成功、暴击和失败判定；重投及复杂关键字继续由玩家手动处理。

## 本地数据迁移

当前存储是“一支卡库对应一份名单”。升级时需要无损迁移：

1. 为 `SavedRoster` 增加稳定的 `rosterId`。
2. 把旧的 `roster_<teamId>` 数据转换为名单数组，每份旧数据生成一个 ID。
3. 新增 `activeRosterId`，代替当前仅记录卡库的 `selectedTeamId`。
4. 迁移成功后保留旧键一个版本周期，避免回退版本后数据完全不可读。

## 平板与手机

- 平板：左侧名单或成员导航，右侧详情；按钮与卡片使用更紧凑的平板密度，避免沿用手机的大触控块。
- 手机：功能完全相同，使用列表 → 详情 → 骰盘的逐页导航；保留当前触控尺寸，不做缩小。
- 两端共用数据和业务逻辑，只允许布局密度与导航方式不同。

## 建议实施顺序

1. 结构化规则词典、武器档案和成员能力。
2. 多名单存储、旧数据迁移及“当前对局小队”。
3. 我的小队列表页。
4. 当前对局小队详情、关键字与能力浮层。
5. 武器选择到骰盘的参数传递。
6. 补充测试：迁移、名单 CRUD、当前选择、规则查阅和骰盘预填。
