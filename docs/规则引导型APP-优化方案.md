# 杀戮小队 APP：规则引导型重构与 UX 优化方案

整理日期：2026-10-20
状态：**规划稿，尚未开发**。另一位开发者正在修改代码，等他完成后，先做一轮最终审计（第 0 阶段），再按本方案实施。
规则依据：《杀戮小队 三版 官中修订版 v11.5》PDF 及 `docs/杀戮小队三版官方规则-v11.5-全文提取.md`。
代码位置均为审计时（2026-10-20）的行号，开工前需重新核对。

## 0. 结论速览

1. **定位**：规则引导型 APP。APP 按标准规则自动推进对局流程、结算骰子、计算 CP 和 VP；双方玩家可以随时撤回，也可以随时人工调整。
2. **边界**：只自动化标准规则的大框架。小队专属规则一律不写进规则引擎，由 6 个通用的人工调整入口承接（见第 4 节）。
3. **撤回必须留痕**：被撤回的操作保留在日志里，以划线方式显示。
4. **权限**：桌面上的双方都可以随时调整，APP 内不做裁判。争议在 APP 外解决。
5. **离场 / 地下**：只用一个特殊状态标记表示，不实际增删特工。
6. **UX 主线**：做减法。能用图形或状态表达的，就不配文字；流程说明删掉；**规则原文一字不删**，收进按需查看的规则面板。

## 1. 设计原则

| # | 原则 | 含义 |
|---|---|---|
| P1 | 引导而非强制 | 标准规则自动推进；遇到小队规则可以覆盖，覆盖时只做提示，不做阻断。 |
| P2 | 一切可撤回，撤回必留痕 | 任何一步都能撤回。撤回本身也是一条日志。 |
| P3 | 人工调整带来源 | 每次人工调整都附一个简短的来源标签，例如“神射手”“指挥重掷”，写入日志。 |
| P4 | 状态胜于说明 | 用颜色、标记、数字表达状态，不用句子描述状态。 |
| P5 | 规则原文不删减 | 规则相关文本必须是原文，并标注 PDF 页码。界面上不放规则的转述或摘要，避免与原文冲突。 |
| P6 | 一屏一事 | 每个步骤只突出一个主操作，其余操作降级显示或收起。 |
| P7 | 小队规则不入引擎 | 不出现 `if (team == ...)` 这类分支。小队相关内容只能是数据（预设、规则文本），不能是代码。 |

## 2. 规则审计结论（待第 0 阶段复核）

### 2.1 已确认的缺陷

| 级别 | 问题 | 位置 | 规则依据 | 修正 |

| 高 | 推进转折点时不发 CP，不决定先手权，不进入战略阶段 | `BattleRoundTransitions.kt:17-28` | 第一转折点之后，没有先手权的玩家改为获得 2CP（p8）；败者获得先手权卡（p106） | 接入已有但未被调用的 `BattleRules.beginTurningPoint`（`BattleModels.kt:189`）和 `BattleFlow.initiative`（`BattleProgress.kt:62`） |

| 中 | 完整流程代码 `BattleControls` 没有任何调用方，`BattleFlowTest` 等测试测的是界面根本不走的路径 | `BattleControls.kt:18` | — | 接入流程，或删除并把测试迁移到真实路径 |

### 2.2 尚未覆盖的标准规则（本次纳入）

- 先手权掷骰和平手规则：平手时由当前没有先手权的玩家获胜；第一转折点平手时，由部署时没有先手权的玩家获胜（p106）。
- 战略阶段：战略计谋需轮流使用或跳过；除“指挥重掷”外，每个转折点同名计谋只能使用一次（p8）。
- 激活时选择命令；APL 修正合计不超过 ±1（p21）；AP 记账；晕眩在下一次激活结束时失效。
- 射击修正入口：制高点（精准 1 / 精准 2，p36）、烟雾（穿刺 2 降为 1，p103）、可移动掩体（豁免改善 1，最多到 2+，p102）、掩护和遮挡来自同一地形时只能二选一。
- 爆炸 X、洪流 X 的多目标结算：每个目标单独建立一套骰池，主界面串联多次射击结算。
- 主要行动改为在第一转折点战略阶段秘密选择（p106）。

### 2.3 已核对、符合规则（保留）

- 射击抵挡保留普通和暴击类型；2 个普通成功抵挡 1 个暴击。
- 致命必须先成功才算暴击。
- 穿刺先减少防御骰，再预留掩护。
- 遮挡降级后不能再升为暴击。
- 严重可以改精准预留的骰子（v1.5 FAQ）；撕裂不能改。
- 重击、撕裂只由自然暴击触发。
- 协助可以叠加；结果为 1 永远失败。
- 近战的格挡、残暴、震荡、轮流重投。
- 受创时命中恶化 1；过热按有效命中判定。
- 装备上限 4 件且不能重复；击杀等级表；主要行动奖励为一半向上取整，单项上限 6VP。

## 3. 撤回与留痕

### 3.1 两层撤回

| 层级 | 范围 | 实现 |
|---|---|---|
| 结算内撤回 | 射击和近战中的每一步：掷骰、重投、保留选择、分配、出击和格挡、人工调整 | 引擎是不可变状态，结算页维护一个 `List<State>` 栈，撤回即出栈 |
| 对局级撤回 | 主界面每次提交：一次完整结算、CP 或 VP 变化、命令切换、阶段推进、状态标记 | 沿用 `BattleStore` 的快照机制（`BattleStore.kt:17-48`）；上限从 30 提高到 100，并持久化 |

结算一旦提交到对局，在对局层就算**一步**。要撤回一整次射击，在主界面撤回这一步即可。

### 3.2 留痕规则

- 日志条目增加状态字段：`ACTIVE | UNDONE`。撤回时不删除条目，而是标记为 `UNDONE`，并追加一条“↶ 撤回：xxx”。
- 显示方式：被撤回的条目用灰色加删除线显示，并保留原始的骰子点数。
- 骰子留痕：撤回一次重投后再重投，新旧点数都留在日志里，例如：~~重投 2 → 5~~ ↶，然后“重投 2 → 3”。这样可以避免“悔骰”的嫌疑。
- 留痕只用来显示，不影响规则计算。被撤回的骰子不保留“已重投”状态，因为它对应的状态本身已经回滚了。
- 撤回按钮显示下一步要撤回的内容，例如“↶ 撤回：瘟疫勇士 耐伤 15→9”。不弹确认框，因为撤回本身也可以通过再操作一次来纠正。
- 自动发生的重要事件用底部提示条代替确认框，提示条上带“撤回”按钮。这类事件包括：特工残废、进入下一转折点、扣 CP。

### 3.3 数据模型草案

```kotlin
data class LogEntry(
    val id: String,
    val time: Long,
    val text: String,            // 已拼接好的完整文本，一条操作只写一条
    val source: String? = null,  // 人工调整的来源标签
    val kind: LogKind,           // RULE / MANUAL / UNDO / SYSTEM
    val undone: Boolean = false
)
```

## 4. 小队规则：通用调整入口

### 4.1 调研结论

我们对 8 支小队、约 210 条效果做了归类（详见附录 A）：

- 约 25%：给武器增加标准武器规则（精准、严重、致命、平衡等），或修改攻击数、命中、伤害。现有的 `ShootingRuleParser` 和 `MeleeRuleParser` 已经能识别这些关键词，**玩家临时加上关键词，引擎就会按标准规则自动结算**。
- 约 20%：减伤、忽略伤害、回复耐伤。
- 约 18%：重投或改判骰子。
- 约 20%：APL、额外行动、激活顺序。
- 几乎每支小队都有持续状态和指示物。
- 少数规则会破坏框架假设：防御方先结算、格挡一次挡 2 个成功、耐伤为 0 但不残废、防御保留成功超过 3 个等。

结论：**不需要任何小队专属代码**。只要提供下面 6 个通用入口，所有观察到的小队规则都可以人工完成结算。

### 4.2 入口一：结算前修饰

- 射击和近战准备页上提供一个“＋ 修饰”按钮，打开底部面板。
- 可以调整的内容：
  - 增删武器规则关键词，从标准词条中选择，带 X 的词条可以选数值。
  - 攻击数、命中、普通伤害、暴击伤害、豁免、防御骰数量，各自 ±。
- 每项修饰可以填一个来源标签（选填）。已生效的修饰在对阵条下方显示为小标签，例如 `+严重 · 神射手`，点击即可移除。
- 作用范围默认是“本次结算”。持续性的效果用状态标记表示（见 4.6）。

### 4.3 入口二：骰子编辑

在任何掷骰步骤，**长按**一枚骰子，弹出菜单：

| 操作 | 典型用途 |
|---|---|
| 重投（选择来源：武器规则 / 指挥重掷 / 其他） | 各种重投来源。选择“指挥重掷”时自动扣 1CP，可撤回 |
| 改点数 | 用预留的骰子替换某枚骰 |
| 改判：失败 / 普通 / 暴击 | 超人体格、埋伏等 |
| 舍弃 | 腐烂诅咒；格挡一次挡 2 个成功时舍弃第二个 |
| ＋ 预留成功（普通 / 暴击） | 冲动决心、额外掩护豁免 |
| 两枚合并为一枚成功 | 狼牙项链、不屈不挠 |

点击（不长按）仍然执行该步骤的标准操作，例如选中这枚骰去重投或分配。

引擎仍然强制执行“同一枚骰最多重投一次”这条标准规则。改点数和改判不会重置“已重投”标记。

### 4.4 入口三：伤害关口与残废确认

- **伤害关口**：扣耐伤之前列出每一枚未被抵挡的成功和它的伤害值。默认直接应用；需要调整时，点某一行可以选择：减 N（设最低值）、改为固定值、暴击伤害按普通伤害算、整枚忽略、+N。
- **流程外伤害 / 治疗**：特工卡上的耐伤条可以直接 ± 调整，用于中毒、反伤、范围伤害、回复等。
- **残废确认**：耐伤降到 0 时，默认残废，并弹出提示条：“XX 已残废 ↶撤回 ｜ 被规则阻止”。
  - 选择“被规则阻止”后，可以保留 X 点耐伤，或附加一个状态标记（如“狂暴”）。
  - 另外提供“不计入击杀”标记，对应“消耗品构体”这类规则。

### 4.5 入口四：近战结算顺序干预

- 可以切换下一个结算方，对应“地下恐惧”“刀刃偏转”等规则。
- 可以连续结算，对应“触觉猎手”。
- 残废后仍可结算一个成功，对应“殉道荣光”：在残废提示条上提供“继续结算一次”。
- 一次格挡挡 2 个成功：用入口二的“舍弃”完成，不另设开关。

### 4.6 入口五：状态标记与小队计数器

- **特工状态标记**：
  - 字段：名称、可选数值、持续时间、来源特工（可选）。
  - 持续时间预设：本次行动 / 本次激活 / 下次激活开始前 / 下次激活结束 / 本转折点 / 下一就绪步骤前 / 整场 / 手动移除。
  - 到期自动移除，移除时写日志。激活开始时，特工卡会高亮提醒带有的标记，例如“中毒”。
- **内置的特殊标记**（仍然只是标记，不改变特工的存在）：
  - **离场 / 地下**：特工卡变暗并显示标记，不计入残废，不影响击杀。是否可以激活、可以做什么由玩家决定。
  - **晕眩**：标准规则效果，由引擎自动添加和移除。
- **小队计数器**：每支队伍可以添加任意数量的命名计数器，例如“节点 3”“隧道 2”“免费指挥重掷 1”，用 ± 调整，可以设置“每转折点重置为 N”。

### 4.7 入口六：流程干预

- CP、VP、APL、AP 都可以手动 ±，并带来源标签。
- 计谋记录支持“0CP 使用”，可在交战阶段使用战略计谋。同名计谋重复使用时只提示，不阻断。
- 激活顺序干预：
  - 额外激活（连续激活）
  - 插入激活（打断对方）
  - 两名特工同时激活
  - 跳过本次激活
  - 反应时更换命令

### 4.8 修饰预设（可选，P5）

- 玩家可以把一组修饰保存为预设，例如“神射手 = 精准 1 + 严重”，之后在“＋ 修饰”面板里一键套用。
- 预设是**数据**（JSON），可以随小队规则资料一起分发，也可以由玩家自己创建。新增小队时不需要改代码。
- 准备页可以加一个“本队规则”抽屉，显示当前小队相关规则的原文，方便对照预设。

### 4.9 引擎需要放开的硬限制

| 限制 | 位置 | 改为 |
|---|---|---|
| 防御骰固定为 3 | `ShootingCombatRules.kt:346` | 基础 3 + 修饰值，下限为 0，不设上限 |
| 防御方额外重投上限为 3 | `ShootingCombatRules.kt:212` | 删除预算概念，改为按需选择重投来源（见 5.3） |
| 必须分配完防御成功才能结束 | `ShootingCombatRules.kt:475` | 保留作为默认引导，并允许“结束分配（人工确认）” |
| 近战固定由攻击方先结算 | `MeleeCombatRules.kt:349` | 默认攻击方先结算，可切换 |
| 骰池只记录计数 | `ShootingDicePool.normals/criticals` | 按 `docs/杀戮小队V11.5-攻防骰规则摘要.md` 第 9 节，改为逐枚骰子建模：来源、是否已重投、转换记录、是否舍弃、是否已用于抵挡。这是入口二的前提 |

## 5. UX 方案

### 5.1 现状诊断（基于 `output/` 下的截图）

| # | 问题 | 证据 |
|---|---|---|
| U1 | 首屏被说明文字占满，主操作在折叠线以下 | 射击准备页：双方卡片加规则提示约占 60% 屏高，“临时重投预算”的长句被截断 |
| U2 | 骰盘面积大、信息少 | 手机近战页两个骰盘各约占 30% 屏高，骰子只占骰盘约 5%；骰子上看不出成功、暴击、失败 |
| U3 | 选择项被藏起来 | 掩护只是一个写着“无掩护”的按钮，点开才是 4 选 1 的对话框；集中武器只剩一个选项，但没有说明原因 |
| U4 | 按钮权重相同、禁用态不明显 | 防御分配用 4 个同样大的橙色按钮，禁用态只是变暗；按钮里“消耗 1 个普通防御成功”与标题重复 |
| U5 | 操作说明在每一步重复出现 | 例如“选择一枚自己的成功进行出击或格挡……”“先手权玩家开始，双方每次只重投一枚……” |
| U6 | 要求提前做决定 | 重投次数要在掷骰之前用步进器填写，与规则“看到结果再决定”的顺序相反 |
| U7 | 页头太重 | 大标题、副标题、独立的返回按钮约占 13% 屏高 |
| U8 | 日志是纯文本 | 没有分组，没有颜色，看不出哪些是撤回、哪些是人工调整；还有孤立行的 bug |
| U9 | 主界面是记录表，不是引导 | 看不出“现在是哪个阶段、轮到谁、该做什么” |

### 5.2 文字分级策略（全 APP 适用）

| 类型 | 例子 | 处理方式 |
|---|---|---|
| **规则原文** | 武器规则、计谋、掩护定义 | **一字不删**。在相关控件旁放 ⓘ 按钮，点开底部面板显示原文和 PDF 页码。界面上不放规则转述 |
| 流程说明 | “选择一枚骰子后重投”“防御方必须亲自分配” | **删除**。由控件本身的状态表达，例如可点的骰子会发光，当前操作方的区域高亮 |
| 状态信息 | “临时重投剩余 1 次”“仍有可分配的防御成功” | 改成徽标、数字或颜色，例如重投来源旁的角标“×1”，未分配的骰子保持高亮 |
| 免责声明 | “应用不会自动扣 CP”“由桌面状态决定” | **删除**。新流程里这些行为由 APP 处理，或通过撤回来兜底 |
| 首次使用提示 | 手势说明，如长按编辑骰子 | 每个提示只显示一次，可以关闭 |

**验收标准**：除规则面板外，每个结算步骤可见的说明文字不超过一行，大约 20 个汉字。

### 5.3 全局框架

- **紧凑顶栏**（高约 56dp）：`← | TP2 · 交战 · A 激活中 | CP A3 B2 | VP 5:4 | ↶`。返回、撤回、阶段信息合在一行。
- **底部主操作区**：固定在拇指能够到的区域，只放当前步骤的 1 个主按钮和最多 2 个次按钮。
- **规则面板**：全局统一的底部面板，显示原文和页码，支持搜索；任何地方的 ⓘ 都打开它。
- **日志抽屉**：从右侧（平板）或底部（手机）拉出。按激活分组；骰子用小图块显示；人工调整显示来源标签；撤回条目用删除线。
- **双方配色**：A 方用橙色，B 方用钢蓝色，沿用现有配色。所有属于某一方的元素（骰子边框、高亮、按钮）都使用这一方的颜色，减少文字里的“攻击方 / 防御方”。
- **平板横屏**：左栏放特工列表，右栏放结算区或详情。手机竖屏为单栏，结算页全屏。

### 5.4 骰子展示

- 骰盘动画播放完后，**收起成一行平铺的骰子图块**。图块高度约 48dp，点数清晰，边框颜色表示判定：暴击为金色，普通为该方颜色，失败为灰色并降低透明度。
- 图块上的小角标：⟳ 已重投；◆ 预留（不显示点数）；✕ 舍弃；✎ 人工改动。
- 骰盘动画作为可关闭的设置项（默认开启）。关闭后直接显示图块，并提供“手动输入点数”，供用实体骰的玩家使用。
- 手机上两方的骰子不再各占一个骰盘，改为上下两行图块，中间放对阵信息。

### 5.5 射击结算页

**准备**（一屏完成，不需要滚动）：

```
┌────────────────────────────────────────┐
│ 喷毒蛇虫 · 螯尾  4A 3+ 3/4   →   瘟疫战士勇士 3+ ♥15/15 │  对阵条（点开看详情）
│ [+严重·神射手 ✕]  [＋ 修饰]                             │
├────────────────────────────────────────┤
│ 掩护   [无][普通][强化·1暴击][强化·2普通]  ⓘ              │
│ 遮挡   [否][是]                                ⓘ         │
│ 制高点 [—][≥2″ 精准1][≥4″ 精准2]               ⓘ         │
│ 烟雾   [否][是]                                ⓘ         │
├────────────────────────────────────────┤
│              [ 掷 4 枚攻击骰 ]                           │
└────────────────────────────────────────┘
```

- 每项都用分段控件，选项直接可见。被武器规则禁用的选项置灰，并在旁边加一个标签说明原因，例如“集中”。点 ⓘ 可以看原文。
- 精准预留数量直接体现在按钮文字里：“掷 3 枚 + 预留 1”。
- 删除“临时重投预算”。

**攻击骰和重投**：

- 只显示骰子图块。可以使用武器规则重投的骰子会发光；点击即重投。
- 点不发光的骰子，弹出“用指挥重掷（−1CP）/ 其他来源”。
- 主按钮：“完成重投”。

**保留选择**（重击、撕裂、严重）：

- 只在这些规则可以触发时出现，形式为开关标签，例如“撕裂：1 普通→暴击”。
- 无法触发的不显示。

**防御**：与攻击相同的流程。显示“3 枚 − 穿刺 1 − 掩护预留 1 = 掷 1 枚”这条算式，让玩家一眼看出防御骰从哪里来。

**分配**：

- 上排是攻击成功图块，下排是防御成功图块。点一枚防御骰，再点一枚攻击骰，完成配对；不合法的目标不响应。
- 顶部显示“推荐分配 · 承伤 4”，点一下套用，套用后仍然可以修改。规则不强制防御方选择最优方案，所以只是推荐，不自动套用。
- 已配对的骰子连线并淡出。实时显示“当前承伤 X”。
- 主按钮：“结算伤害”，进入伤害关口（4.4）。默认无调整时，直接一键应用。

**结果**：一屏总结，包括伤害、残废、晕眩、过热。主按钮为“完成并返回”，次按钮为“对下一目标射击”（用于爆炸 / 洪流）。

### 5.6 近战结算页

- **对峙布局**：上方是对手的骰子图块，下方是自己的。当前结算方的一侧高亮，并显示“轮到你”的箭头，不再用句子说明。
- **点骰即用**：点自己的一枚成功，就地弹出两个按钮：“出击 −4♥”和“格挡 →”。选格挡后，对手可以被格挡的骰子发光，点选目标即可。残暴、震荡等规则限制直接体现在哪些骰子能被选中。
- 删除现在的 4 个大按钮。
- 双方耐伤条放在各自骰子行旁边，出击后实时扣减。
- 协助：准备页提供 `协助 [0][1][2][3]` 分段控件，有效命中实时更新。

### 5.7 对局主界面

```
┌ 顶栏：TP2 · 交战 · 轮到 A ─────────── CP 3:2  VP 5:4  ↶ ┐
│ 阶段条：先手 ✓ ─ 就绪 ✓ ─ 战略 ✓ ─ ●交战 ─ 结束          │
├──────────────┬────────────────────────┤
│ A 小队（橙）  │ 特工卡网格 / 选中特工详情                  │
│ B 小队（蓝）  │                                           │
└──────────────┴────────────────────────┘
│ 底部主操作：[ 激活特工 ]   次：[计谋] [结束转折点]        │
```

- **阶段条**：始终可见。每一步由 APP 自动完成（发 CP、发先手权卡、就绪特工），完成后弹提示条，提示条上可撤回。需要玩家输入时（掷先手权骰、选择战略计谋），底部主按钮变成对应的操作。
- **特工卡**（紧凑）：
  - 头像
  - 名字
  - 耐伤条，受创时变色
  - 命令标记：交战 / 隐匿
  - 就绪 / 待机，用卡片亮或暗表示
  - 状态标记小圆片，最多显示 3 个，多余的显示为 +N
  - 残废时显示灰色和骷髅标记；离场时显示虚线框和标记
- **激活流程**：点特工 → 选命令 → 进入激活面板。面板上显示 AP 点数，以及行动按钮：移动、冲锋、后撤、冲刺、射击、近战、拾取、自定义。射击和近战进入结算页；其他行动只记录并扣 AP。主按钮“结束激活”，结束后自动轮到对方。
- **反应**：在“轮到 B”时，如果 B 方有符合条件的特工，额外显示一个“反应”按钮。
- **终局**：第四转折点结束后自动进入总结页，内容包括：
  - 各项 VP 明细：主要行动奖励、击杀等级、击杀等级 +1
  - 胜负结果
  - 关键事件时间线
  - 完整日志（可展开）

### 5.8 开局设置

- 改成分步向导：小队 → 装备 → 关键行动 → 战术行动（秘密） → 开始。
- 每步一屏，顶部用进度点表示进度，不写说明段落。
- 秘密选择用“交给对方 / 遮挡屏幕”的交互完成，沿用现有的 `SecretSelection`。
- 主要行动的选择移到第一转折点的战略阶段（见 2.2）。

### 5.9 视觉细则

- 尺寸层级只用 4 级：页内标题、正文、次要文字、数字。数字（耐伤、CP、VP、伤害）用等宽加粗字体。
- 主按钮使用该方颜色的实心底，次按钮用描边，禁用态用低透明度描边。禁用态必须和可点状态有明显区别。
- 触控目标不小于 48dp。桌面场景下手可能不干净、离屏幕较远，所以关键按钮做到 56dp 以上。
- 动效：伤害数字飘出，耐伤条平滑扣减，撤回时状态回滚的动画。时长不超过 200ms，不阻塞操作。
- 支持横竖屏，并且旋转时状态不丢失（已有截图 `tablet_shooting_rotated.png` 需要回归测试）。

## 附录 C：实施记录（2026-10-21）

已完成第 0–4 阶段的主体内容，并在手机（1080×1920）和平板（2560×1600）模拟器上逐步实测。单元测试共 133 项，全部通过。截图在 `output/rule-guided/`。

### 第 0 阶段复核结论
2.1 中的缺陷在对方改完后依然存在，本轮已全部修复：
- 开局缺少 CP 和先手权
- 转折点推进不发 CP
- 手动扣耐伤不触发残废
- 终局缺少击杀奖励和胜负判定
- `BattleControls` 没有调用方
- 重投日志被拆成两行

### 规则流程
- 新对局从「决定先手权」开始。先手拼骰支持平手规则：第一转折点比部署时的先手方，之后比当前先手方。
- 自动处理：发 CP（第一转折点各 +1；之后没有先手权的一方 +2）、发先手权卡、就绪特工、交战阶段由先手方开始。
- 战略阶段双方轮流使用计谋或跳过；同名计谋重复使用时先提示，确认后仍可记录。
- 激活：激活时选择命令，记录 APL / AP（晕眩会 −1，修正合计不超过 ±1）。行动不符合核心规则时，可以填写依据后「按规则例外记录」。支持反应、放弃反应和额外激活（规则干预）。
- 残废与计分：
  - 耐伤归零自动残废；提示条提供撤回、「被规则阻止」、「不计入击杀」三个选项。
  - 击杀等级每提升一级自动 +1VP，复活特工不会扣回。
  - 终局击杀等级较高的一方 +1VP，揭示主要行动并判定胜负，显示总结页。
- 旧存档兼容：已经达到的击杀等级视为已经计过分，不会重复加分。

### 撤回与留痕
- 对局级撤回最多 100 步。被撤回的记录保留并标为已撤回，在完整记录中以删除线显示，同时追加一条「↶ 撤回：…」。撤回按钮会显示下一步要撤回的内容。
- 射击和近战的结算页内，每一步都可以撤回；被撤回的过程按时间顺序以删除线显示，并随结果一起写入对局记录。

### 小队规则的通用入口（不含任何小队专属代码）
- 修饰：增删标准武器规则，调整攻击、命中、伤害、豁免、防御骰数量，可填写来源。
- 骰子：点任意一枚骰子，可以选择重投来源（武器规则 / 指挥重掷自动扣 CP / 其他），也可以改判、舍弃、改点数，或「＋ 预留」一个成功。每枚骰仍然只能重投一次。
- 伤害关口：逐个调整每一击的伤害。近战支持舍弃对手的成功、改由对方结算、直接调整耐伤。
- 状态标记：名称和数值可以自定义，提供 7 种持续时间并会自动到期。「离场 / 地下」和「晕眩」作为内置标记。
- 小队计数器：可以设置每转折点重置。

### UX
- 每页上方是紧凑顶栏（返回 / 阶段 / 撤回），下方是固定操作栏，提示条显示在操作栏上方。
- 掩护、遮挡、制高点（目标隐匿时不获得精准）、烟雾、精准预留都直接平铺显示；被武器规则禁止的选项会注明原因。
- 骰子显示为大图块：暴击为金色，失败为灰色；已重投、已改动的骰子有角标。骰盘在掷完后会缩小。
- 防御分配采用「点防御骰 → 点攻击骰」的方式，并提供推荐分配，可一键套用。
- 近战改为上下对峙的布局，点自己的成功骰就地选择出击或格挡。
- 规则原文：12 个规则主题和 22 条武器规则从全文提取文档逐字导入（`tools/extract_core_rules.py` → `assets/core_rules.json`），点 ⓘ 或武器关键词即可查看，并注明页码。

### 尚未实现（建议下一轮）
- 修饰预设（例如「神射手 = 精准 1 + 严重」）以数据形式保存和分发。
- 主要行动仍在开局前选择，按规则应移到第一转折点的战略阶段。
- 可移动掩体（豁免 +1）还没有单独的开关，目前用「修饰 → 豁免」处理。
- 开局设置页、编成页还没有按 5.8 重做。

## 附录 F：VP 窗口与通用掷骰（2026-10-22）

- VP 窗口：点 ± 时窗口不再关闭再重开，数字在原地更新；窗口打开期间不重绘背后的对局界面，关闭时统一刷新一次。消除了闪烁。
- 通用掷骰（`DiceRolls.kt` / `DiceSheet.kt`），依据规则书 p23「骰子(D6、D3)」：
  - 支持 xD6、xD3（D3 = D6 减半向上取整）、加值，例如 D3+3、2D6；
  - 可设目标值 y+，逐骰判定成功（结果为 1 永远失败）；
  - 点骰子可重掷一次，同一枚骰最多重掷一次，且必须接受新结果；
  - 常用预设：D6、D3、2D6、2D3、D3+3、D3+1、D6·3+、D6·4+（按小队规则资料里的出现频率选取）。
- 入口：对局页顶栏「掷骰」，以及射击、近战结算页顶栏。对局页掷出的结果可以填写用途，写入完整记录（分类「掷骰」，可撤回）。

## 附录 G：掷骰统一为骰盘动画（2026-10-24）

- 全 APP 只用一种掷骰方式：`DiceTrayView` 3D 骰盘动画，加上骰子音效。
  - 通用掷骰窗口：顶部固定一个骰盘。“掷”和点骰子重掷都在骰盘里播放动画，结果以动画落定的点数为准。D3 由 D6 面值换算。
