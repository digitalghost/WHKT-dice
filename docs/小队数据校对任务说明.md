# 小队数据校对任务说明（每个代理负责一支小队）

项目：/Users/alanliu-15air/Projects/anroid1st（Android 杀戮小队对局记录 APP）。用中文工作。

你负责的小队已经由脚本生成了两份**骨架**，你要把它们校对成可上线的成品：

1. `app/src/main/assets/teams/<TEAM_ID>.json` —— 特工、武器、专属能力、专属武器规则
2. `app/src/main/assets/rules/<TEAM_ID>.json` —— 阵营规则、计谋、阵营装备、编成、标识指南

格式规范：`docs/小队数据JSON格式.md`（务必先读）。**成品样例**（已人工校对、可直接参照写法与粒度）：
`app/src/main/assets/teams/KT-BROOD_BROTHERS.json`、`app/src/main/assets/rules/KT-BROOD_BROTHERS.json`。

资料来源（只读）：
- 卡图：`docs/<小队>-卡片提取/*.png`（**唯一权威**，用 Read 工具直接看图）
- 卡面文字层：`docs/<小队>-卡片提取/manifest.json`（cards[].text，两栏常混排，只作辅助）
- 整理资料：`docs/<小队>-完整规则资料.md`（第 6 节特工能力、第 13 节更新日志 / 勘误）

## 必做

**teams JSON**
- 每个特工：核对 APL/移动/豁免/耐伤、每件武器的攻击/命中/伤害/规则、远程或近战（卡面武器图标：枪=远程，刀=近战），与数据卡图逐一一致。
- 填 `role`（卡面关键字行中的定位，如 领袖/战士/炮手/医务兵）、`baseSizeMm`（资料里有就填，没有填 null）。
- 同名特工（骨架里会出现“XX（2）”这种重名）通常是同一张卡的不同武器配置或识别错误：按卡图判断应合并为一个特工还是确为不同特工，并改成卡面真实名称。
- `defaultWeaponIds`：按编成卡（小队选择）中的默认/第一种装备选项；拿不准就保留全部。
- `abilities`：**逐张看数据卡和能力卡图**，把卡上每一个专属能力、独特行动（带 xAP 的）完整转录：`{"name","ap","text"}`。两栏混排要理顺成连贯段落，不概括、不漏字；勘误（资料第 13 节）并入正文。
- `weaponRules`：卡面带 * 的专属武器规则，按卡图补全 `text`。卡面规则若被骨架误标 *（核心规则如“撕裂”“致命 5+”“穿刺”），从 weaponRules 删除。
- `subtitle`：形如“阵营 · 子阵营 · N 种成员”；`archetypes`：编成卡“原型：”一行。
- 全部完成后**删除 `"draft": true`**。

**rules JSON**
- 骨架正文来自资料文档，可能有两栏混排、断句、漏行：逐条对照卡图修正；把资料第 13 节对应勘误并入正文。
- 跨两张卡的规则已合并为一条（cards 有两张图），确认正文包含两张卡的全部内容。
- 完成后**删除 `"draft": true`**。

## 校验（必须全部通过）

```
python3 -I tools/check_team_data.py <TEAM_ID>
python3 -I tools/check_team_rules.py
```

check_team_data 会对照 manifest 文字层核对数值；若你确认文字层有误而卡图为准，可以在 teams JSON 的特工上加 `"verifiedAgainstImage": true` 并在汇报中说明。

## 约束
- 只改你负责的这两个 JSON；不要改 Kotlin、不要改其他小队的文件、不要删除或重命名任何文件、不要提交 git。
- 卡图引用保持现有文件名（.png），不要改扩展名。

## 补充（来自 XV26 试点）

- **先看卡图**：先 Read 全部数据卡 / 能力卡 / 规则卡图，再对照 manifest 的武器字段；`完整规则资料.md` 只用来查勘误（第 13 节常有两栏混排，勘误页最好也直接看 PDF 渲染图或卡图）。
- **多张卡同名**（如多张“XV26-数据卡”）：按卡面真实名称命名特工，`cards` 里引用对应卡图即可；校验脚本按卡图引用判定覆盖，不再要求名称与 manifest 标题一致。
- **默认武器**：数据卡列出全部可选武器时，按编成卡的第一种选项给默认；编成卡没提到的武器（如装备类）不放进默认。
- **多段能力**：用 `• ` 开头的分行；表格（如数值对照表）改写为“条件：效果”的逐行文字。
- 卡图在 APP 里是 .webp，JSON 中仍写 .png 文件名，APP 和校验脚本都会自动对应。

## 补充（来自第一批：胡蜂尖翼）

- **卡图可能被裁切**：数据卡缺武器行、或有带 * 的规则却看不到定义时，渲染 PDF 原页核对：
  `pdftoppm -f <页> -l <页> -r 150 -png "docs/最新杀戮小队规则更新/<…>.pdf" /tmp/<队>-p<页>`，再用 Read 看图。
- **“请继续阅读背面规则”**的卡，背面可能没被切成卡图，同样去 PDF 原页补全。
- **卡面已含部分勘误**：逐条比对勘误与卡面，卡面已是新文字的照录，未更新的再并入。
- **勘误与问答**：rules JSON 里应有一条 category 为“勘误与问答”的条目，收录资料第 13 节的勘误与 Q&A 原文。
- 卡面上不属于任何特工能力、而是解释武器规则的文字块（如“中子辐射”），放进对应的 weaponRules 正文里。

## 补充（来自第一批：曼德拉）

- **优先级**：卡图与勘误冲突时，**勘误优先**（卡图可能印刷早于勘误）。规则：卡图 > 文字层；勘误 > 卡图。
- **默认武器**：小队选择卡没有给武器选项（每名特工配置固定）时，`defaultWeaponIds` 保留全部武器；同一武器的多种模式都列为默认。
- **勘误与问答条目**：id 用 `<TEAM_ID>-errata`，category 用“勘误与问答”，`cards` 可为空列表，正文收录勘误原文与问答。
- **图标 / 表格类卡**：标识指南写成“本小队专属标识与指示物：A、B、C”；装备里的武器表写成“名称（远程/近战）：攻击 4，命中 3+，伤害 3/4；武器规则：…”。
- **环境**：本机没有 `rtk`，命令不要加 rtk 前缀；在 /tmp 写含中文的 Python 脚本时，用 `python3 -I -X utf8` 运行，或 `exec(open(path, encoding='utf-8').read())`。

## 补充（来自第一批：虫刃）

- **卡面译文可能出错**（如“穿刺”漏了数值）：用英文 PDF（`docs/最新杀戮小队规则更新_EN/`）交叉确认，按英文含义取舍，并在汇报里写明“卡面原文 / 改为 / 依据”。
- PDF 原件位置：中文 `docs/最新杀戮小队规则更新/`，英文 `docs/最新杀戮小队规则更新_EN/`。勘误页直接渲染 PDF 看，比资料第 13 节可靠。
- 校验脚本已修复：不带连字符的 ID（如 WYRM）现在也会逐张核对卡图；武器行下方以 * 开头的脚注不再被误判为专属规则。

## 补充（来自第一批：特种兵）

- **武器的说明性脚注**（如“*请注意，洪流 0" 意味着……”）：写进该特工一条能力里会被校验拒绝（名称不在卡面）。放法：若对应带 * 的专属规则，写进 weaponRules 正文；若只是对核心规则的提示，写进 rules JSON 的“勘误与问答”条目。
- **勘误译文与卡面/英文冲突**：以英文 PDF 为准取舍，在汇报中写明；正文不加编者注，原始勘误保留在“勘误与问答”条目里。
- **队长多种武器组合**：`weapons` 收录全部武器，`defaultWeaponIds` 取编成卡列出的第一种组合。
- 在 /tmp 写含中文全角符号的 Python 脚本，第一行加 `# -*- coding: utf-8 -*-`，或用 `python3 -X utf8` 运行。

## 补充（来自第一批：侦查小队）

- **勘误与卡图谁新谁旧要先判断**：有的卡图比勘误更新（如侦查小队「匿迹转移」：卡图与英文卡面一致，勘误是旧文字）。取舍顺序：
  1. 卡图与英文 PDF 卡面一致 → 以卡图为准，旧勘误只留在“勘误与问答”条目；
  2. 卡图仍是旧文字、勘误是新文字 → 勘误并入正文；
  3. 无法判断 → 以英文 PDF 为准，并在汇报中列出。
- 读勘误页推荐：`pdftotext -layout "docs/最新杀戮小队规则更新_EN/<队名> 杀戮小队规则.pdf" -` 看英文勘误，比中文资料第 13 节清楚。
- 骨架的武器规则常整体错位到下一行武器、或缺 ` · ` 分隔；校对时每件武器的规则字段都要对照卡图逐项核对，不能只看数值。
- rules 正文出现“• AP。”这类残片说明骨架混排严重，整条按卡图重写。

## 补充（来自第一批：凯恩之刃 / 卡舍津 / 军团 / 探路者）

- **校验单队**：`python3 -I tools/check_team_rules.py <TEAM_ID>` 只校验指定小队，别的队失败不影响你；规则卡匹配已忽略 .png/.webp 扩展名，卡图文件名标题有误（如“名称攻击命中伤害”）时条目标题可写卡面真名。
- **原型用 APP 词表**：渗透 / 侦察 / 安全保护 / 搜索与摧毁（卡面写“搜索与破坏”也填“搜索与摧毁”），编成正文照卡面。
- **多原型小队**（原型取决于编入内容，如凯恩之刃）：archetypes 全部列出。
- **勘误第 13 节当核对清单用**：卡面已含的勘误不要重复并入。
- **多选项规则**（如混沌印记）：总条目列全选项，各子卡另保留独立条目。
- **编成选项无武器数据的装备**（如微光护盾）记为能力；**阵营规则卡里附带的武器档案**写在规则正文里，不建武器条目。
- **控制字符**：部分 manifest 标题/卡图文件名含 `\x07`（如 `MB3\x07侦察无人机`）。Read 打不开时先复制成普通文件名；特工名用卡面真名并加 `verifiedAgainstImage: true`。
- **规则表格只在 PDF 页面上**（如探路者标记光 1–5 枚指示物表）：对照 PDF 渲染页补全。
- **骨架 rules 的 entries 若不是数组**（被压缩成字符串），整体按卡图重建。
- 编成正文用“• / ○”两级列表。
