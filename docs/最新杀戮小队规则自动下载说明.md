## 0. 给 Agent 的一分钟速查

```bash
cd /Users/alanliu-15air/Projects/anroid1st

# 1) 只看会下载什么 / 会排除什么（不落盘）
python3 tools/download_kill_team_rules.py --list

# 2) 下载 / 增量更新全部「中文版 + 各小队自己的规则」PDF
python3 tools/download_kill_team_rules.py
```

* **只下小队自己的规则**：输出目录里**只有**官方 `Team Rules`（小队规则）分类的文档——
  APL 数据表、特工档案、武器、战术指令。**任务包、战役系统、核心规则、通用装备、更新日志一律不下载。**
* **幂等**：已下载且官方文件未更新的条目自动跳过。实测一次全量增量重跑约 **8 秒**（48 份全部 `unchanged`）。
* **自愈**：每次运行都会用 `HEAD` 比对远端 `Content-Length`，本地文件若被截断会自动重下（见 §6.1）。
* **自动清理**：若上一轮下载过、但本轮已不符合筛选条件（例如官方把文档改分类、或切换了筛选规则），
  脚本会删除对应的本地文件，保证输出目录始终只含合规内容。
* 想强制重下：`--force`；想临时把任务包等通用内容也拉下来：`--include-general`（默认关闭）。
* 每次运行都会重写 `docs/最新杀戮小队规则更新/manifest.json`（来源 URL、官方更新日期、SHA256、被排除清单）。
* 官方 PDF 属 GW 版权资料，`.gitignore` 已忽略 `docs/最新杀戮小队规则更新/*.pdf`（不入库），`manifest.json` 保留入库。

## 1. 页面是怎么工作的（为什么不能直接抓 HTML）

官方下载页是 **Next.js 应用**：

| 事实 | 证据 |
| --- | --- |
| 服务端直出的 HTML 里**没有**下载条目 | `curl https://www.warhammer-community.com/en-gb/downloads/kill-team/` 后检索 `\.pdf`、`shared-download`、`download_categories` 均无命中；页面只有 `downloads-accordion` 骨架 + 加载遮罩 |
| 下载列表由前端异步请求接口获取 | 页面 JS chunk `chunks/174-*.js` 的 `DownloadsProvider` 调用 `POST /api/search/downloads/` |
| 官方 CDN 存放 PDF | 下载卡片组件把 `id.file` 拼成 `https://assets.warhammer-community.com/{file}` |

因此脚本**复刻官方接口调用**，既不解析 DOM，也不受页面改版影响。

### 1.1 接口

```http
POST https://www.warhammer-community.com/api/search/downloads/
Content-Type: application/json

{"index":"downloads_v2","searchTerm":"","gameSystem":"kill-team","language":"chinese"}
```

响应关键字段：

```jsonc
{
  "totalHits": 69,
  "params": "filters=locale:en-gb AND game_systems:kill-team AND download_languages:chinese&hitsPerPage=500&page=1",
  "hits": [
    {
      "title": "冥工之环",                 // 中文标题
      "download_languages": "chinese",
      "download_categories": ["team-rules"],    // 官方分类（决定是否小队专属）
      "id": {
        "slug": "canoptek-circle",
        "file": "chi_canoptek_circle_online_rules-fso2rcause-39cwws25fo.pdf",
        "file_size": "12.93 MB",
        "created_at": "26/08/2026",
        "last_updated": "26/08/2026"
      }
    }
  ]
}
```

实测数据量（2026-10 抓取）：`game_system=kill-team` 全部语言共 **528** 条 = 69 个文档 × 8 种语言（韩语少 24 条）。
其中 **中文（language=chinese）69 条**，与英文条目 `slug` / `last_updated` **一一对应**，所以脚本可用英文接口补全英文标题。

### 1.2 官方分类表（Kill Team 下载页）

SSR 负载里的 `download_categories` 共 23 项，其中 Kill Team 实际有内容的只有 3 个：

| 分类 slug | 含义 | 处理 |
| --- | --- | --- |
| `team-rules` | **各杀戮小队自己的规则**（APL 数据表 / 特工 / 武器 / 战术指令） | ✅ 下载 |
| `faction-packs` | 各阵营自己的规则包（Kill Team 目前为空，保留以适配官方调整） | ✅ 下载 |
| `mission-packs` | **任务包 / 战役系统**（炽血与虔诚、协作行动系列、泰图斯、泰希斐斯探索…） | ❌ 排除 |
| `key-downloads` | 核心规则、简化规则、通用装备、锦标赛手册、更新日志、地形模版 | ❌ 排除 |

其余分类（`faqs-and-errata`、`indexes`、`spearhead`、`combat-patrol`、`warband-rules`、`terrain-rules`、`organised-play`、`lore` …）在 Kill Team 下**没有条目**（属于其它游戏系统），脚本对它们天然免疫。

## 2. 下载过滤规则（对应需求 2）

### 2.1 只下载中文版

接口参数 `language=chinese`（简体中文）。官方语言代码为
`english / german / spanish / french / italian / japanese / chinese / korean`。
想换语言：`--language english` 等。

### 2.2 只下载「每个小队自己的规则」，任务包一律排除

判定只依据**官方分类**，一条规则、零歧义：

```
下载  ⟺  download_categories ∩ {team-rules, faction-packs} ≠ ∅
排除  ⟺  其余全部（mission-packs / key-downloads / ...）
```

**为什么不再做“文件名启发式 + PDF 首页文本嗅探”？**
早期版本曾用两条启发式规则捞出「看起来像小队规则」的文档，结果捞进了 3 份**任务包**（已删除）：

| 曾被误收的文件 | 文件名/首页特征 | 真实内容 | 结论 |
| --- | --- | --- | --- |
| 泰希斐斯 探索 Ctesiphus Expedition | 文件名含 `team_rules` | 首页写明「泰希斐斯探索是一个基于地图的**战役系统**……在六角形地图上探索」 | ❌ 是战役系统，不是小队规则 |
| 蚁牛 Ambull Mission Pack | 首页「包含了蚁牛天罚特工和它的两个凿洞虫群的**规则**」 | 是**任务包**（含 2 个任务 + 1 支天罚特工及其规则） | ❌ 是任务包 |
| 归档者 The Archivist Mission Pack | 首页「包含了归档者天罚特工的**规则**」 | 是**任务包**（含 2 个任务 + 1 支天罚特工及其规则） | ❌ 是任务包 |

官方分类 `team-rules` 已经准确表达了「这份文档就是某支小队自己的规则」，直接采信官方分类比任何猜测都可靠。
现在输出目录里的 48 份文档，**全部**首屏为 APL 数据表 / 特工档案 / 武器表，可自行复核。

## 3. 文件存放与命名

```

├── 冥工之环 Canoptek Circle 杀戮小队规则.pdf
├── 死亡天使 Angels of Death 杀戮小队规则.pdf
├── 蛇虫 Raveners 杀戮小队规则.pdf
├── ……
└── manifest.json
```

命名规则：`<官方中文标题> <官方英文标题> <后缀>.pdf`

* 后缀由官方分类决定：`team-rules` → `杀戮小队规则`；`faction-packs` → `阵营规则`。
* 与仓库既有命名（`docs/死亡天使 Angels of Death 杀戮小队规则.pdf` 等）保持一致。
* 非法字符（`/ : * ? " < > |`）会被替换为空格。

`manifest.json` 结构：

  "generated_at": "2026-10-25T01:05:00+08:00",

## 4. 命令行参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `--out-dir` | `docs/最新杀戮小队规则更新` | 输出目录 |
| `--game-system` | `kill-team` | 游戏系统 slug（可换 `warhammer-40000` 等） |
| `--language` | `chinese` | 下载语言 |
| `--include-general` | 关 | 连任务包、核心规则等通用内容一起下载（默认只下各小队自己的规则） |
| `--force` | 关 | 忽略本地已有文件强制重下 |
| `--list` | 关 | 只打印「会下载 / 会排除」清单，不下载 |
| `--workers` | `4` | 并发下载线程数（实测 6–8 更快） |
| `--no-english-titles` | 关 | 不补英文标题（离线或接口异常时使用） |

### 4.1 增量与自愈机制

* **文件级增量**：以 `slug` 为键比对上一轮 `manifest.json` 的 `source_file`；官方换版本时文件名哈希会变，
  因此会自动重下并清理旧文件名。
* **完整性自检**：跳过前先 `HEAD` 一次比对 `Content-Length`，不一致则重下（见 §6.1）。
* **自动清理**：上一轮下载过、本轮已不符合筛选条件的本地文件会被删除（本次即删除了 3 份任务包）。
* 因为判定完全基于官方分类，**不需要任何探测性下载**，一次增量重跑仅约 8 秒。

## 6. 故障排查

### 6.1 已踩过的坑：CDN 提前断流导致文件截断

**现象**：`胡蜂尖翼 Vespid Stingwings` 与 `猎手支队 Hunter Clade` 两份 PDF 用 `pdftotext` 报
`Couldn't read xref table`，但 MuPDF 能容错读出文本——典型的「文件尾部缺失」。

**根因**：CDN 并发大时连接提前关闭，urllib 把短读当正常 EOF 收下，本地文件比远端声明长度少
（13 375 637 / 13 561 132、18 491 102 / 19 413 678 字节）。

**处理**：脚本做三重校验，任意一项不过就重试：

1. `GET` 响应里的 `Content-Length` 与实际写入字节数必须相等；
2. 与官方 `file_size` 字段（`12.93 MB` 这类）对比，偏差 > 2% 判失败；
3. 文件头必须是 `%PDF`；
4. 每次运行的「跳过」分支也会先 `HEAD` 比对长度，发现本地不完整自动重下。

**验证**：修复后重跑，两份文件自动重下成功；48 份全部通过 `pdftotext` 独立解析，
且本地字节数与远端 `Content-Length` **逐份一致**。

### 6.2 其它

| 现象 | 处理 |
| --- | --- |
| 接口返回 `totalHits: 0` | 官方临时限流/改路径。等几分钟重试，或用 `--list` 验证；脚本已内置 4 次退避重试 |
| 文件名带 `.part` 残留 | 下载中断的临时文件，下次运行会自动清理 |
| 某份小队规则没出现 | 先 `--list` 看它是否落在 `team-rules` 分类；若官方改分类，脚本会随之调整 |
| 想要任务包/核心规则 | `--include-general`（默认关闭，注意该目录会混入非小队规则内容） |
| 想换下载源语言 | `--language english`（注意英文是同一批文档的译本） |

## 7. 给后续 Agent 的检查清单

1. 先读本文件，确认脚本路径与输出目录。
2. 执行 `python3 tools/download_kill_team_rules.py --list` 查看判定是否符合预期。
3. 执行 `python3 tools/download_kill_team_rules.py` 完成下载（约 8 秒的增量检查，或数分钟的全新下载）。
4. 检查 `docs/最新杀戮小队规则更新/manifest.json` 的 `counts` 与 `skipped`，确认没有把任务包/通用规则混进来。
5. 自查输出目录纯净度：`ls docs/最新杀戮小队规则更新/ | grep 任务包` 应无输出。
6. 需要把规则喂给 APP 时，参考同目录既有流程：
   `tools/extract_pdf_rules.rb`（PDF → 规则文本）、`tools/extract_team_mark.py`（小队标记）。
7. 若官方新增了小队：无需改代码，重跑脚本即可——新条目走「分类 → 下载 → 写入 manifest」流程。
