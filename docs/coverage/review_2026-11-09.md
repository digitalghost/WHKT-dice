## 二、需要更正的描述（不影响结项）

报告里有几处统计口径不对，数字偏大或者指的不是那回事。功能没有问题，只是报告不准确：

| 报告中的说法 | 实际情况 |
| :--- | :--- |
| 「制高点 / 精准 51 次」 | 导出记录里没有任何「制高点」「精准」字样，App 本身也不记录精准预留。报告引用的行其实是「不掷骰预留」，也就是手动预留成功骰 |
| 「残暴 14 次」 | 导出记录里没有「残暴」字样，引用的行只是普通近战。截图 `match_01/CORE-WR-04_5556.png` 能看到「格挡不可用：对方武器残暴，只能用暴击格挡」，所以**残暴按钮的行为是对的**，但日志引用的数字不实 |
| 「强化掩护 10 次」 | 引用的是「掩护预留 0 普通、1 暴击」，那是用暴击骰保留的掩护，不一定是强化掩护。导出记录不区分这两种，无法从日志核实 |
| 不掷骰预留 | 68 次「不掷骰预留」都没有填写规则依据。这次不影响结算核对，但正式对局中应填写来源 |

另外，77 次射击中有 43 次「掷骰数 + 预留数」比武器攻击骰数少 1~2 枚。这可能是精准预留，App 不写日志，也可能是测试者调了「＋修饰」的攻击骰数，从记录上无法区分。

## 三、给开发的两条小建议（可选）

1. **精准预留没有写进日志。** `ShootingCombatRules` 的过程日志只记录「不掷骰预留」，没有记录 `accurateRetained`。这样导出记录看不出制高点 / 精准是否生效，复盘也看不出哪些骰子是精准保留的。建议在攻击骰日志前加一句「精准预留 N 个普通成功」。
2. **「不掷骰预留」的依据建议改为必填**，或者在日志里标注「未注明依据」，方便复盘时识别手工干预。

这两条都不是规则错误，可以放到之后的版本。
