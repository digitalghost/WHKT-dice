## 1. 一分钟概览

- **是什么**：把桌游《杀戮小队》第三版做成 PC 电子游戏的 Godot 4 工程（GDScript），目录 `kt-game/`，与仓库根目录的 Android 辅助器（`../app`）互相独立。
- **能玩到什么程度**：死亡天使（IMP-AOD）对瘟疫战士（CHAOS-PM），在沃库斯六张官方地图上，从战前流程一路打到第 4 转折点结算。支持单人对 AI 和双人热座。
- **验证到什么程度**：
  - 单元测试 251 项全过（`tests/run_all.gd`）。
  - AI 对 AI 全程对局 192 局无失败、无脚本错误（`tests/scenario_playtest.gd`，只测引擎层）。
  - 截图巡检 13 张无脚本错误（`--autotest-screenshots`）。
  - **界面没有被人完整手动玩过一局**。最近几轮的交互修复和新功能按钮只有单元测试和截图，没有真人点过。这是当前最大的不确定性。
- **最要紧的未完成项**：爆炸 / 洪流武器只打主要目标（第 4.1 节）；界面层试玩与人工验收没做（第 6 节）。

## 2. 环境与常用命令

在仓库根目录执行（Godot 4.7，路径 `/opt/homebrew/bin/godot`）：

```bash
./kt-game/run.sh                                                          # 启动
godot --headless --path kt-game -s res://tests/run_all.gd                 # 单元测试，应为 251 PASSED, 0 FAILED
godot --headless --path kt-game -s res://tests/scenario_playtest.gd -- --seeds=20            # 全程对局，报告在 build/playtest/report.md
godot --headless --path kt-game -s res://tests/scenario_playtest.gd -- --seeds=12 --all-tacs # 强制 12 张战术行动都被选到
godot --path kt-game -- --autotest-screenshots                            # 截图巡检，输出 build/screenshots/
godot --path kt-game -- --autotest-screenshots --map=volkus_25_02         # 指定地图
python3 kt-game/tools/build_volkus_map.py all                             # 重新生成六张地图
python3 kt-game/tools/build_glossary.py                                   # 重新生成规则词典
python3 kt-game/tools/sync_assets.py                                      # 从 ../app 同步卡图、头像、字体等
```

接手时要注意的环境事实：

- **被 git 忽略、需要自己生成的目录**：`assets/cards/`、`assets/portraits/`、`assets/ui/`、`assets/fonts/` 由 `sync_assets.py` 从 `../app` 生成；新检出后不跑这一步界面会缺图。
- **`external-assets/`（约 6 GB，TTS 模组解包）被忽略**，只在原开发机上有。重新生成地图、解 Unity 资源包、导入新 token 都依赖它。没有它也能运行和测试，只是不能重建地图和补素材。
- **解 Unity 资源包**用的是 `build/venv` 里的 UnityPy（`build/` 被忽略），需要时自己 `pip install UnityPy pillow`。
- **GDScript 把“无法推断类型”当错误**：从 Dictionary / Array / JSON 取值必须写显式类型，不要对 Variant 用 `:=`。
- 改了 PNG / OBJ 后要跑一次 `godot --headless --path kt-game --import`。
- 仓库根目录 `../app` 下有大量未提交改动，是别人的工作，与本工程无关，不要动。
- 退出时的 `ObjectDB instances were leaked` / `resources still in use` 是既有的无害告警。

## 3. 必须遵守的约束（项目所有者定的）

1. **一切以原始规则为准**。规则原文在 `../docs/杀戮小队三版官方规则-v11.5-全文提取.md`；小队规则与所有中文文字以辅助器的中文资源为准（`data/teams/*.json`、`data/core/core_rules.json` 即由其同步而来）。
2. **外部素材只取模型和 token**。`external-assets/` 里的卡片已过期，其规则文字不可采信，不得使用。
3. `../docs/UI设计方案/` 是辅助器的，不要和本游戏混用。本游戏的美术说明在 `docs/UI_ART_BRIEF.md`。
4. **保留可见的英寸尺度**（格线、量尺），这是桌游感的一部分。
5. 术语用规则书的写法：“隐匿”不是“隐秘”。
6. 目标平台先 PC，移动端以后再说（尚未开始）。

## 4. 代码结构

约 2.1 万行 GDScript。

| 文件 | 行数 | 职责 |
|---|---|---|
| `src/core/kt_engine.gd` | 3389 | 状态机、战前流程、行动、装备、战术行动、计分、撤销栈 |
| `src/core/kt_combat.gd` | 975 | 射击与近战结算、武器规则、阵营规则修正 |
| `src/core/kt_geometry.gd` | 629 | 移动路径与费用、可见性、掩护、遮挡、控制范围 |
| `src/core/kt_ai.gd` | 311 | AI 决策 |
| `src/core/kt_data.gd` | 307 | 小队与地图加载 |
| `src/ui/main_game.gd` | 4004 | HUD、各阶段界面、输入、AI 调度、截图巡检 |
| `src/ui/dice_combat_modal.gd` | 1328 | 骰盘（先手、射击、近战） |
| `src/board/killzone_view.gd` | 2420 | 3D 棋盘、相机、交互模式、叠加层 |
| `src/board/kt_models_3d.gd` | 1128 | 地形、装备、棋子、token 的 3D 构建 |
| `tests/run_all.gd` | 2230 | 单元测试 |
| `tests/scenario_playtest.gd` | 330 | 全程对局测试 |

**阶段顺序**（`state["phase"]`）：
`DROPZONE` → `SELECT` → `EQUIP` → `TACOP` → `EQDEPLOY`（有需部署的装备时）→ `DEPLOY` → `INITIATIVE` → `STRATEGY` → `FIREFIGHT` → …（4 个转折点）→ `GAME_OVER`

**需要知道的几个设计事实**：

- **全部状态在一个字典 `engine.state` 里**，撤销就是 `var_to_str` 整体快照（最多 30 步）。
- **2.5D 几何**：地形是带高度的轴对齐矩形（`heavy_wall` / `heavy_low` / `light` / `vantage` / `razor_wire`），每个平面坐标只有一个高度。**同一位置不能既有楼上又有楼下**——特工站进制高点矩形就算在楼上。这是很多简化的根源（见 5.3）。
- **未部署的特工坐标是 `(-99, -99)`**，任何按坐标做事的代码都要先判 `deployed`。
- **阵营规则是按 `op_id` / `team_id` 硬编码在引擎和战斗代码里的**，不是数据驱动。加第三支小队要改代码，不是只加 JSON。
- **数据文件由脚本生成，不要手改**：`data/maps/*.json`（`build_volkus_map.py`）、`data/core/glossary.json`（`build_glossary.py`）。
- 战术行动文字在 `data/core/tac_ops.json`，通用装备文字在 `data/core/universal_equipment.json`。

## 5. 已知缺陷与未完成项

按“对实际对局的影响”从大到小排。每条注明是**已确认**（读过代码或跑过）还是**未验证**。

### 5.1 规则：会打出错误结果的

1. **爆炸 x / 洪流 x 没有次要目标**（已确认）。
   数据里破片手雷、疫病手雷、喷火手枪、自动爆矢步枪、重型爆矢枪、瘟疫喷吐炮等都带 `blast` / `torrent`，但 `src/core` 里没有任何代码读这两个键，`create_shooting_session` 永远只建单目标会话。规则见规则书 p.92 与第 2730–2742 行。这是当前最大的规则缺口，需要新的多目标结算流程和对应界面。

2. **近战“空格挡”和“暴击格挡选普通骰”引擎支持了，界面没接**（已确认）。
   `src/ui/dice_combat_modal.gd` 约 1289 行：对手没有成功骰时“暴击弹反”按钮仍被禁用；1295 行普通招架同理。`execute_melee_step` 的 `prefer_normal` 参数界面上没有入口。规则 p.18。

3. **制高点相关的两处近似**（已确认，审计遗留）。
   - 遮挡判定用高度启发式（`kt_geometry.gd` 里 `maxf(z_a, z_d) < th + 1.5`），规则 p.36 说的是“与制高点相连的重型地形不算”。
   - 交战命令目标被制高点射击时，总是多给一枚普通掩护豁免；规则允许防御方二选一（改为保留一枚关键成功）。见 `kt_combat.gd` 掩护豁免部分。

4. **关键行动 op 只实装了“占领”**（已确认）。
   认证行动 2025 共 9 张关键行动卡，游戏固定用占领，没有选卡步骤。规则书 p.108–109 是图片，提取不出文字，`_score_key_op_end_of_tp` 的计分**没有对照原卡核实过**。辅助器 `../app/.../MissionCards.kt` 里有社区速查版文字可参考。

5. **堡垒专属规则没做**（已确认）：拥挤堡垒致命 5+、门与访问点、破拆。地图数据里没有门 / 访问点实体，所以装备部署规则里“距访问点 2" 外”也没有检查。

### 5.2 通用装备与战术行动的简化

这些都能用，但与规则有出入（已确认）：

- **通讯装置、破拆炸药**可以选，但对这两支小队在沃库斯上没有任何效果（没有“支援”规则、没有突破点）。数据里仍标 `implemented: true`。
- **爬梯**：按“攀爬路径离爬梯够近”判定，没有绑定它靠的是哪块地形。
- **可移动掩体**：不区分护盾内侧 / 外侧和支架。
- **翻越**：同一段路径连续翻两件轻型地形只算一次 +2"。
- **地雷**：先放地雷、后放其他标识时，没有反向检查“距地雷 2" 外”。
- **烟雾**：没有“不影响标识下方”的上下层切分；震荡手雷 1" 波及只看平面距离。
- **插旗**：旗帜放在执行者脚下，不能另选落点。
- **放置装置**的计分对卡面做了解读：敌方半场的目标有己方装置 +1，敌方正在争夺的其他目标有己方装置 +1。“敌方目标”按目标点落在谁的领地判断，中线上的不属于任何一方。
- **扫荡清理**按规则书 V11.5 勘误（p.111）计分，与 `tac_ops.json` 里的速查文字不完全一致。
- **战术行动文字来源是社区速查**（风来西行动速查 vol.1.29），不是官方原卡。
- **两支首发小队的原型都是“安全保护 + 搜索与摧毁”**，所以侧翼、放置装置、回收、追踪敌军、敌情、窃取情报这 6 张在正常对局里选不到，只被测试强制指定跑过。

### 5.3 地图与几何

- **目标点贴墙**（已确认）：只保证目标点中心离不可通行矩形 ≥ 0.25"。地图 1、2、3、4、5 各有一个目标点离墙 0.28"–0.69"，小于标识半径 0.79"，视觉上标识会压到墙。地图 1、4 上特工无法正好站在目标点中心（仍可在控制范围内争夺）。
- **目标点在制高点矩形内**（已确认）：7 个目标点落在楼板矩形里（官方图上它们在堡垒 / 废墟内部的地面层）。由于 2.5D 限制，游戏里它们算在 3" 高的楼板上，要爬上去才能争夺。这与桌面实际不符，但要解决得先支持“同一位置两层”。
- **规则矩形是 0.5" 网格近似**，墙体比真实模型略粗。
- **装备模型与规则尺寸不一致**（已确认）：模型只按长边等比缩放。重型掩体模型深 0.50" / 高 1.45"，规则 0.7" / 1.9"；可移动掩体、轻型掩体也有出入。碰撞和视线用规则矩形，所以看到的和判定的略有差别。
- 地图坐标与朝向约定是对六张官方地图图片数值拟合出来的，写在 `build_volkus_map.py` 的“Coordinate conventions”注释里。**不要凭直觉改符号**，之前在这上面错过三次。

### 5.4 界面与交互

- **以下操作没有真人点过**（未验证）：携掩体移动、烟雾选点、震荡选目标、弹药储备重掷按钮、侦查选目标、插旗、夺旗、拾取标识、搜索、清理、放置装置。
- **以下显示没有在截图里出现过**（未验证）：爬梯 / 弹药储备 / 通讯装置 / 地雷的模型；飞蝇云、殉道者、主宰、特使、旗帜、情报、装置、扫荡标记；受创、APL±1、命令指示物“已激活”暗面。
- **最近一轮交互修复只有单元测试**（未验证）：空格键不再被按钮吞掉、AI 回合禁用撤销且一次回到玩家上一步、Esc 取消 / F 复位相机、数字键 8 / 9 / 0 去重、开新局清理旧骰盘、覆盖层打开时暂停 AI。请优先人工过一遍。
- **地形闪烁**的修复（地形抬高 0.02"、地垫下移 0.01"）只看了静帧，运行中是否还闪需要确认。
- **战术行动缺少的显示**（已确认没做）：侧翼分界线与归属色；“战术行动进度”面板（如“侧翼：西 ✔ / 东 ✘”）；选点模式按行动显示不同提示文字。
- 第 3 个及以后的独特行动没有快捷键；“携盾”槽复用了转移图标。
- **热座模式没有遮挡**：秘密选人、选装备、选战术行动、选主要行动都在同一块屏幕上依次进行，对手能看见。
- 死亡天使在外部素材里没有专属 token，用的是通用标记。

### 5.5 AI

- 战前全部用默认值：不换降落区、默认名单、只拿阵营装备、默认战术行动。
- 不会用烟雾手雷、震荡手雷、补充弹药，也不会用任何需要选目标的行动（如侦查）。
- 72 局强制指定战术行动的对局里，追踪敌军、敌情、击溃一次分都没拿到；特使、殉道者、放置装置、窃取情报得分率也很低。规则有单元测试覆盖，但 AI 不会为它们走位。
- 审计没有覆盖 `kt_ai.gd` 的规则正确性。

### 5.6 测试自身的弱点

- 几条断言太弱，几乎不可能失败：`first in ["A", "B"]`、`ai_step.has("kind")`、`phase != "GAME_OVER"`。
- `_test_combat_audit_fixes_and_factions` 把攻击者放在墙边并手动覆盖 `obscured` / `cover`，没有断言 `valid`。
- 装备部署测试里按地形 `kind` 反推装备种类，而不是按放下去的东西核对。
- 全程对局测试只走引擎接口，**不经过界面层的处理函数**，查不出界面与引擎之间的接缝问题。

### 5.7 数据与素材的零碎

- 词典里“持徽手”“传染圣像”“排斥韧性”的一句话说明与全文相同（数据源本身只有一句）。
- `assets/tokens/` 里有几张导入了但没用到的图（四种手雷、`guard.png`）。
- 棋盘上的阵亡标记部分情况下仍是 ☠ 字符。

## 7. 工作方式上的经验

- **改规则前先查规则书原文并在注释里写页码或行号**。审计发现的 12 条规则缺陷，大多是凭印象写的。
- **改地图或几何后，把规则矩形叠到官方地图图片上看**（`external-assets/killzones/volkus/boards_and_mats/tile_volkus_approved_ops_2025_*.png`），比读坐标可靠得多。
- **测试里不要硬编码“碰巧可用”的坐标**。地图重建过两次，每次都有测试因为站位落进墙里而“因错误的原因通过”。
- **截图巡检不报错不等于功能可用**。它只证明没有脚本错误；按钮能不能点、点了对不对，要么写经过界面回调的测试，要么人工点。
- 本工程曾把部分编码交给另一个本地代理（提交信息里标了“agy 编写”），现已停用。那些提交都经过了 diff 复核和测试，但复核不等于试玩，第 5.4 节的“未验证”项很多出自那几轮。
